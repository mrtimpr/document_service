# Отчет о соответствии дипломного проекта требованиям

Дата повторной проверки: 31 июля 2026 года.

## Результат

Проект соответствует технической части задания и содержит реализацию всех
обязательных функций. Единственный критерий, который нельзя выполнить внутри
архива, — фактическое размещение исходного кода в удаленном Git-репозитории.
Для его закрытия необходимо отправить проект в GitHub, GitLab или другой
удаленный репозиторий по инструкции из `README.md`.

## Исправления после повторного аудита

1. В сериализатор загрузки явно добавлены валидаторы расширения и размера файла.
   Без этого переопределенное поле DRF могло не наследовать валидаторы модели.
2. Добавлены тесты недопустимого расширения и превышения размера файла.
3. При `DEBUG=False` проект больше не запускается без обязательного `SECRET_KEY`.
4. Swagger и ReDoc явно открыты для просмотра, тогда как рабочие API защищены.
5. Настройки Celery усилены подтверждением задач после выполнения и повторной
   доставкой при потере worker-процесса.
6. Добавлены русские модульные docstring, docstring функций и поясняющие
   комментарии по правилам PEP 8.
7. Добавлены Flake8 и воспроизводимый скрипт `scripts/audit_project.py`.
8. Диапазоны зависимостей актуализированы для Django 5.2, DRF 3.16–3.17, Celery 5.6, drf-spectacular 0.30 и Psycopg 3.3.

## Проверки перед сдачей

```bash
python scripts/audit_project.py
ruff check .
flake8 .
python manage.py makemigrations --check --dry-run
pytest
```

В CI последние четыре проверки запускаются автоматически. Порог покрытия
зафиксирован на уровне 75%; при меньшем результате сборка завершается ошибкой.

## Ограничения проверки архива

Статическая проверка синтаксиса, структуры и конфигурации выполнена при сборке
архива. Полный интеграционный запуск требует установленных зависимостей,
PostgreSQL и Redis. Рекомендуемый способ окончательной проверки —
`docker compose up --build` и запуск `pytest` либо отправка проекта в GitHub,
где проверки выполнит workflow `.github/workflows/ci.yml`.
